# Engineering Conventions

## 1. Layering Law
- **API (`app/api/`)**: Thin HTTP routers. Parse inputs via Pydantic schemas, call services, return responses. Never touch DB sessions directly.
- **Services (`app/services/`)**: Business logic & orchestration. Never import FastAPI `Request`/`Response` or raise HTTP exceptions; raise `AppError` subclasses.
- **Repositories (`app/repositories/`)**: Database queries only. Never call `session.commit()` inside a repository; the request/service boundary owns transactions.
- **Models (`app/models/`)**: SQLAlchemy 2.x async ORM definitions.

## 2. Async Rules
- All routers, services, and repository methods must be `async def`.
- Never execute blocking I/O (sync HTTP, heavy PDF parsing, CPU-bound work) on the event loop; offload to `asyncio.to_thread()` or background workers.
- Every outbound HTTP/API call must define an explicit timeout.
- Avoid SQLAlchemy lazy loading in async sessions (`MissingGreenlet` risk); always use explicit `selectinload()` or `joinedload()`.

## 3. Database & Migration Rules
- Every schema change goes through Alembic (`alembic revision --autogenerate`). Never edit tables manually in production/dev GUIs.
- Always review autogenerated migration scripts and ensure `downgrade()` works cleanly.
- Never modify a migration that has already been applied/committed.
